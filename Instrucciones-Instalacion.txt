OPERATIV — Instrucciones de instalación y ejecución
=====================================================

1. BASE DE DATOS (SQL Server Express o Developer)
--------------------------------------------------
Ejecutar los scripts de la carpeta Database\ EN ORDEN, contra una instancia
de SQL Server (SSMS, Azure Data Studio, o sqlcmd):

    01_CrearBaseDatos.sql          -> crea la base "Operativ" y todas las tablas
    02_DatosSemilla.sql            -> catálogos, patentes, familias y usuario inicial
    03_IntegridadDVH_DVV.sql       -> script histórico (sin objetos); el cálculo de
                                       DVH/DVV vive ahora en Operativ.Comun.IntegridadHelper
                                       y Operativ.DAL.SistemaDAL (punto 8 de las mejoras)
    04_ProcedimientosSeguridad.sql -> script histórico (sin objetos); el acceso a datos
                                       de Usuario/Familia/Patente/Bitácora es CommandText
                                       parametrizado en Operativ.DAL
    05_ProcedimientosNegocio.sql   -> script histórico (sin objetos); ídem para
                                       Cliente/Paquete/Suscripción/Pago/Factura/Activo/Incidente
    06_BackupRestore.sql           -> únicos SPs vigentes: backup y restore de la base
    07_CalcularIntegridadInicial.sql -> calcula el DVH/DVV inicial de los datos semilla
                                       (script de uso único, sin SPs; ejecutar una sola vez,
                                       antes del primer login — ver nota más abajo)

Con sqlcmd, desde la carpeta Database:
    sqlcmd -S .\SQLEXPRESS -E -i 01_CrearBaseDatos.sql
    sqlcmd -S .\SQLEXPRESS -E -i 02_DatosSemilla.sql
    sqlcmd -S .\SQLEXPRESS -E -i 03_IntegridadDVH_DVV.sql
    sqlcmd -S .\SQLEXPRESS -E -i 04_ProcedimientosSeguridad.sql
    sqlcmd -S .\SQLEXPRESS -E -i 05_ProcedimientosNegocio.sql
    sqlcmd -S .\SQLEXPRESS -E -i 06_BackupRestore.sql
    sqlcmd -S .\SQLEXPRESS -E -i 07_CalcularIntegridadInicial.sql

IMPORTANTE: 07 debe ejecutarse sí o sí antes del primer login. La app verifica
la integridad DVV de Usuario en cada inicio de sesión (UsuarioBLL.IniciarSesion);
sin este paso, DigitoVerificadorTabla queda vacía y el primer login fallará con
ERR22 (integridad corrupta). Después de la instalación inicial, "Reparar Base de
Datos" ya está disponible desde la app (Administración, perfil Web Master) para
recalcular DVH/DVV cuando haga falta — 07 solo cubre el arranque en frío, cuando
todavía no hay ninguna sesión autenticada para llegar a esa pantalla.

Usuario inicial (perfil Web Master), creado por 02_DatosSemilla.sql:
    Usuario:  webmaster
    Clave:    Admin123!   (marcada como temporal: el sistema pedirá cambiarla en el primer login)

2. CONFIGURACIÓN DE LA APLICACIÓN
--------------------------------------------------
Editar Operativ.Web\Web.config:
  - connectionStrings:Operativ -> ajustar Data Source/Initial Catalog/credenciales a tu instancia.
  - appSettings:ClaveMaestraAes -> reemplazar por un valor secreto propio.

3. COMPILAR
--------------------------------------------------
Requiere .NET Framework 4.7.2 Developer Pack instalado (o superior) y el SDK
de .NET (para MSBuild/dotnet build). Desde la raíz de la solución:

    dotnet build Operativ.sln

Esto compila las 6 librerías de clases (BE, Comun, SEC, DAL, BLL, WebServices)
y el proyecto Operativ.Web hacia Operativ.Web\bin\Operativ.Web.dll.

4. EJECUTAR (IIS Express / IIS)
--------------------------------------------------
Operativ.Web es un proyecto Web Forms clásico (System.Web): las páginas .aspx
se sirven directamente desde la carpeta del proyecto y ASP.NET las vincula en
tiempo de ejecución con las clases code-behind ya compiladas en bin\Operativ.Web.dll.
No usa Kestrel/ASP.NET Core.

Opción A - Visual Studio (recomendado):
  1. Abrir Operativ.sln (requiere el workload "Desarrollo web y ASP.NET").
  2. Click derecho sobre Operativ.Web > "Establecer como proyecto de inicio".
  3. Presionar F5. Visual Studio reconoce Operativ.Web como Proyecto de Aplicación
     Web (Web Application Project) y lo levanta automáticamente con IIS Express
     en un puerto libre, sin configuración manual adicional.
     Si en algún momento aparece "A project with an Output Type of Class Library
     cannot be started directly", es porque el .csproj quedó en formato SDK
     simple; ya está corregido para usar el formato clásico de Web Application
     Project (con ProjectTypeGuids + WebProjectProperties), que es el que VS
     necesita para ofrecer IIS Express como opción de ejecución.

Opción B - IIS Express manual (sin depender de la integración de VS):
     "C:\Program Files\IIS Express\iisexpress.exe" /path:"C:\Users\Matias\Operativ\Operativ.Web" /port:8080
  Luego abrir http://localhost:8080/Login.aspx

Opción C - IIS local:
  Crear un sitio/aplicación en IIS apuntando a la carpeta Operativ.Web,
  con Application Pool en modo "No Administrado" (.NET CLR version = No Managed Code
  no aplica aquí; usar la versión clásica de .NET Framework 4.x del pool).

5. NOTAS
--------------------------------------------------
- Operativ.Web y Operativ.WebServices usan el formato clásico de csproj (Web
  Application Project), el segundo para poder exponer sus tres operaciones
  como Web Services SOAP reales (IncidentesService.asmx, CatalogoService.asmx,
  ResumenSuscripcion.asmx, con [WebMethod]). Las 4 librerías de clases
  restantes (BE, Comun, SEC, DAL) usan el formato moderno (SDK), más simple de
  mantener; ambos formatos se pueden referenciar entre sí sin problema. El
  Facade de Operativ.BLL sigue siendo el único canal de acceso desde la UI:
  instancia esas clases directamente (referencia de proyecto), sin pasar por
  un proxy SOAP generado.
- Los XML de salida de los Web Services (incidente_*.xml, catalogo_paquetes.xml,
  resumen_suscripcion_*.xml) se generan en Operativ.Web\App_Data\XmlGenerado\
  (se crea automáticamente en la primera ejecución), usando XmlTextWriter.
- Módulos marcados como "implementación mínima" en el código (Pago, Factura,
  Activo, Incidente) tienen su capa de base de datos y DAL completas; la capa
  de negocio (BLL) cubre los flujos principales y queda documentada con
  comentarios "ver Operativ.BLL.XxxBLL" para quien quiera extenderlos.
